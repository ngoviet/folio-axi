# folio-axi

<!-- readme-axi type=tool -->

[English](README.md) · **Tiếng Việt**

Folio mở các trang HTML do agent tạo trong trình duyệt trên máy, để bạn chỉ vào từng phần tử, đánh dấu chữ và sơ đồ, rồi gửi phản hồi luôn tới đúng phiên Claude Code đã tạo ra trang đó.

Folio dựng trên [lavish-axi](https://github.com/kunchenguid/lavish-axi) 0.1.96 của Kun Chen (MIT), do [ngoviet](https://github.com/ngoviet) bảo trì cho Claude Code trên Windows. Folio không phát hành lên npm. Bối cảnh, kế hoạch và trạng thái (tiếng Việt): [docs/folio/README.md](docs/folio/README.md).

Những gì Folio thay đổi so với lavish-axi:

- **Phản hồi tới đúng phiên agent.** `folio-axi <file>` ghi lại phiên Claude Code đã mở trang (`FOLIO_SESSION_ID`, do hook SessionStart xuất ra). Poll từ phiên khác nhận `NOT_OWNER`, trừ khi truyền `--takeover`. Muốn tiếp quản một trang đã có chủ thì cần session ID; trang chưa có chủ thì tiếp quản được mà không cần.
- **Không mất im lặng.** `poll` chỉ ack một lô sau khi đã in nó ra; poll bị dừng trước lúc đó sẽ nhận lại đúng lô ấy ở lần sau. Câu trả lời của agent không tính là ack.
- **Hook lo cho phiên đang hoạt động; poll chạy nền có theo dõi đánh thức phiên đang rảnh.** `folio-axi setup hooks --write` thêm bốn hook Claude Code: SessionStart (danh sách trang ngắn gọn của thư mục này, dưới 1.500 ký tự, rỗng khi không có trang nào), Stop (đưa phản hồi chưa đọc cho agent, tối đa 3 lần liên tiếp, và với mỗi lượt giao thì nhắc một lần chạy `folio-axi poll` nền có theo dõi cho trang đã có chủ mà chưa ai nghe, chặn lặp bằng `hook-poll-reminders.json`; `FOLIO_AXI_STOP_HOOK=0` tắt hook này), UserPromptSubmit (thêm phản hồi đang chờ vào lượt kế tiếp) và SessionEnd (báo cho server biết phiên đã đóng, để các trang phiên đó làm chủ nói rõ không còn ai đọc những gì được gửi; SessionStart của phiên được tiếp tục sẽ nhận lại trang). Hook chỉ chạy khi phiên đang hoạt động, nên chính poll mà chúng nhắc chạy mới là thứ đánh thức phiên khi người dùng gửi từ trang.
- `folio-axi end <file>` vẫn chạy khi tệp HTML đã bị xoá; các bản ghi phiên đã kết thúc đủ điều kiện được dọn lúc khởi động sau 7 ngày (`FOLIO_AXI_ENDED_RETENTION_DAYS`); `state.json` được ghi nguyên tử (atomic).
- Windows: server cũ được dò bằng `netstat`, server khởi động không mở cửa sổ console, hook dùng thư mục hồ sơ người dùng của Windows.
- Chạy song song với lavish-axi: trạng thái ở `~/.folio-axi`, cổng `4388`, biến môi trường `FOLIO_AXI_*`. Không telemetry, không Agent Plugin, không hook Copilot/Codex/OpenCode.

SDK của trang giữ nguyên tên của lavish-axi, nên artifact viết cho Lavish chạy được mà không cần sửa: `window.lavish.*`, thuộc tính `data-lavish-*`, dòng comment Mermaid `%% lavish-icon` và message `lavish:*`.

HTML là markdown mới. Folio là trình biên tập mới cho các artifact HTML của bạn.

Agent làm artifact HTML phong phú rất giỏi, nhưng vòng cộng tác giữa người và agent trên các artifact đó còn thiếu, đành quay về ảnh chụp màn hình và những câu trả lời dài kiểu “hãy nói tôi cần sửa gì.”
Như vậy là mất đi thứ HTML làm tốt nhất: tính tương tác.

Folio mở các tệp HTML do agent tạo trong trình duyệt trên máy, cho bạn chỉ đúng phần tử và đoạn chữ đã chọn, sửa các sơ đồ agent viết bằng Mermaid dưới dạng bảng trắng, rồi gửi phản hồi để agent xử lý.

- **Ưu tiên chạy cục bộ** - Review artifact HTML cục bộ bằng CLI cục bộ, vòng phản hồi chính không phụ thuộc đám mây; chia sẻ qua dịch vụ bên thứ ba ht-ml.app chỉ diễn ra khi bạn chủ động bật.
- **Người và AI cùng làm** - Chú thích phần tử và đoạn chữ đã chọn, sửa sơ đồ bảng trắng Mermaid, và nhắn cho agent mà không rời Folio.
- **Có sẵn mọi thứ cần** - Folio dạy agent cách trình bày trực quan tốt cho các trường hợp thường gặp như kế hoạch sản phẩm hay kỹ thuật, thử nghiệm thiết kế và nhiều thứ khác, dùng được ngay.

Folio là một [AXI](https://axi.md), nghĩa là -

- Nó chỉ là một CLI mà agent đủ năng lực nào cũng chạy được, không cần thiết lập.
- Nó được tối ưu để agent dùng thuận tiện. Output TOON, long polling và cách chỉ nêu thông tin khi đúng ngữ cảnh giúp nó rất tiết kiệm token.
- Skill và hook dưới đây chỉ lo phần giúp agent biết tới công cụ; agent học dùng AXI bằng chính việc dùng nó.

## Cài đặt

Folio không phát hành lên npm. Trong thư mục mã Folio (Node 22 trở lên, pnpm), cài các gói phụ thuộc và link CLI cục bộ:

```sh
pnpm install
npm link
folio-axi setup hooks          # preview
folio-axi setup hooks --write  # merge Claude Code hooks into ~/.claude/settings.json
```

Khởi động lại phiên Claude Code sau khi cài hook. Hook chạy thẳng `bin/folio-axi.js` của thư mục mã này bằng `node`, bỏ qua shim của npm (đường dẫn có ký tự không an toàn với shell thì quay về `folio-axi` trên PATH), nên nếu chuyển thư mục mã đi nơi khác thì chạy lại `folio-axi setup hooks --write`. `npm link` không tự build: sau khi kéo mã mới về, chạy `pnpm run build`. Skill `skills/folio` trong repo chỉ agent tới phần help, hướng dẫn thiết kế và playbook hiện hành của CLI. Bạn cũng có thể bảo agent dùng thẳng `folio-axi`.

## Cách dùng

1. Agent viết một trang HTML, mặc định đặt trong `.folio/` của dự án.
2. `folio-axi .folio/plan.html` mở trang đó trong trình duyệt. Hãy dùng Chrome hoặc một trình duyệt thông thường khác: trình duyệt tích hợp của app Claude chặn khung sandbox trên địa chỉ cục bộ.
3. Agent chạy `folio-axi poll .folio/plan.html` thành tác vụ nền có theo dõi rồi kết thúc lượt.
4. Bạn chú thích phần tử hoặc đoạn chữ đã chọn, trả lời các câu hỏi trên trang, rồi bấm **Gửi cho agent**. Poll chuyển ghi chú của bạn cho đúng phiên đã mở trang.
5. Agent trả lời bằng `folio-axi reply` (hoặc `poll --agent-reply`) rồi poll tiếp. **Gửi và kết thúc** trên trình duyệt, hoặc `folio-axi end` từ phía agent, sẽ đóng lượt review.

## Cách hoạt động

```
┌───────────────┐
│ Agent writes  │
│ artifact.html │
└───────┬───────┘
        ▼
┌────────────────────────┐
│ folio-axi <file_path> │
│ opens local browser UI │
└───────┬────────────────┘
        ▼
┌────────────────────────┐
│ Human annotates text   │
│ or elements, sends     │
│ chat, or queues layout │
│ issues from the inbox  │
└───────┬────────────────┘
        ▼
┌────────────────────────┐
│ folio-axi poll waits  │
│ and returns prompts    │
│ the user queued        │
└────────────────────────┘
```

- **Định danh bằng đường dẫn tệp** - Phiên được định danh bằng đường dẫn chuẩn hoá của tệp HTML, nên agent không phải giữ các ID vô nghĩa.
- **Artifact mang đi được** - Artifact chạy trong iframe sandbox, còn Folio chèn một SDK nhỏ cho chú thích, ảnh chụp DOM, điều khiển phản hồi và kiểm bố cục lúc hiển thị.
  Link và popup do tác giả định nghĩa có thể mở ở tab cấp cao nhất, còn tài liệu artifact vẫn nằm trong sandbox, không có quyền same-origin.
  Folio không chèn design system nào, nên tệp HTML đã lưu hiển thị y hệt dù bạn mở qua `folio-axi` hay mở thẳng trên trình duyệt.
  Chạy `folio-axi design` để xem nguồn duy nhất của hướng dẫn thiết kế dành cho agent, gồm các đoạn mã CDN tuỳ chọn và đoạn mã bật bảng trắng (Mermaid).
- **Cảnh báo tự tô nền** - `folio-axi <html-file>`, `export` và `share` chạy một phép kiểm không cần render, tìm artifact thiếu nền trang khai báo rõ ràng, và trả về một dòng `self_paint_warning`.
  Phép kiểm theo kiểu fail-open - chỉ cần có link stylesheet, `@import`, script runtime của Tailwind, `color-scheme`, hay dấu hiệu nền ở `html`/`body`/`:root` là không cảnh báo - và không bao giờ chặn việc mở trang.
- **Màn che kiểm bố cục khi mở** - Khung review trên trình duyệt (chrome) chỉ che artifact trong lúc lượt kiểm thật trong iframe chờ phông chữ và bố cục cuối.
  Lượt kiểm phía trình duyệt đầu tiên hoàn tất là artifact hiện ra, bất kể nó tìm thấy gì và kể cả khi gửi kết quả lên server thất bại; màn che không bao giờ giữ lượt review lại để chờ sửa lỗi hay chờ một vòng mạng.
  Người dùng có thể bấm **Vẫn hiển thị**, và một hạn chờ an toàn có giới hạn sẽ mở màn che ở mọi trạng thái.
  Nếu lượt review hoàn toàn không tải được - script của chính khung review không chạy, hoặc server không trả lời yêu cầu tải artifact sau vài lần thử lại - màn che nêu rõ vấn đề và đưa nút **Kiểm tra và tải lại**, vẫn giữ lối thoát **Vẫn hiển thị** độc lập.
  Nếu server có artifact mà trình duyệt không bao giờ chạy nó - trình duyệt tích hợp của Claude chặn khung sandbox trên địa chỉ cục bộ, nên hãy dùng Chrome hoặc trình duyệt khác - một thẻ trong vùng artifact hiện link review kèm **Chép link** và **Vẫn hiển thị**. Agent không được báo, vì vấn đề nằm ở trình duyệt của người review chứ không phải ở artifact.
  Lượt review đã tải ở một tab trình duyệt khác cũng được báo theo cách đó, kèm nút **Tiếp quản ở đây** để tải artifact trong tab hiện tại, vì mỗi lúc Folio chỉ tải một artifact trong một tab. Cảnh báo tiếp quản ghi: "Câu trả lời chưa gửi nằm lại ở thẻ hoặc cửa sổ nơi bạn nhập; tiếp quản ở cửa sổ khác không mang chúng theo."
- **Hộp lỗi bố cục** - Việc phát hiện diễn ra thụ động. Sau khi phông chữ và các hiệu ứng chuyển động có hạn chạy xong, SDK được chèn xác nhận lỗi nghiêm trọng dựa trên bằng chứng hiển thị trực tiếp, như nội dung có ý nghĩa hoặc nút điều khiển cần dùng tràn ra ngoài đáng kể, đoạn chữ bị cắt, phần tử không với tới được trong khổ màn hình, hoặc bị che gần như toàn bộ về mặt ngữ nghĩa.
  Dấu ba chấm và line clamp khai báo rõ, chữ trợ năng ẩn theo cách chuẩn, vùng cuộn hay mask có chủ ý, phần thò ra khỏi phần tử cha, số đo cuộn chung chung của phần tử, chồng lấp mang tính trang trí và chuyển động chưa chắc chắn, tự chúng không tạo ra lỗi.
  Lỗi đã được chứng minh được xếp vào nút **Lỗi bố cục** trên thanh trên cùng; nút này ẩn khi không còn lỗi nào chưa xử lý, còn không thì hiện số lỗi chưa xử lý.
  Ngăn kéo của nút liệt kê từng lỗi với mức độ nghiêm trọng, lời giải thích dễ hiểu, khổ màn hình bị ảnh hưởng, định danh đích/thành phần, lần thấy gần nhất và trạng thái vòng đời, kèm hai thao tác cho từng lỗi: **Chỉ chỗ** (tô sáng nó trong artifact) và **Bỏ qua**.
  Mặc định không chọn gì. Người dùng chọn các lỗi (hoặc **Chọn tất cả**) và **Xếp hàng sửa mục đã chọn** biến cả nhóm đó thành một prompt chờ bình thường, gắn nhãn `layout-warnings`, tới agent theo đường phản hồi thông thường khi người dùng gửi.
  Việc phát hiện không bao giờ làm `folio-axi poll` trả về và không bao giờ đánh thức agent; chỉ khi người dùng xếp hàng một yêu cầu sửa thì mới có. Ngoại lệ duy nhất là phản hồi `artifact_failures` nghiêm trọng, dành cho lỗi khiến chính lượt review không dùng được, như tài liệu artifact hoặc một tài nguyên cục bộ của nó không tải được.
- **Vòng đời lỗi bố cục** - Mỗi lỗi được nhận diện bằng một dấu vân tay ổn định gồm luật chẩn đoán, định danh đích đã chuẩn hoá và loại khổ màn hình, nên phát hiện lặp lại chỉ cập nhật một bản ghi chứ không làm số đếm tăng lên.
  `Đang mở` nghĩa là lượt kiểm hoàn tất gần nhất ở khổ màn hình của nó vẫn thấy lỗi. `Đang chờ sửa` nghĩa là người dùng đã yêu cầu sửa - lỗi vẫn tính là chưa xử lý và vẫn được đếm, và không xếp hàng lại được khi yêu cầu đó còn đang chờ.
  `Đã xử lý` đòi hỏi một lần tải artifact mới hơn thành công cộng với một lượt kiểm đầy đủ ở cùng khổ màn hình không còn thấy lỗi; khi đó lỗi ra khỏi số đếm nhưng vẫn giữ một lịch sử có giới hạn.
  `Vẫn còn` (tái diễn) nghĩa là một lỗi đã xếp hàng vẫn tồn tại qua phiên bản mới hơn, nên lại chọn được, kèm lần thử trước được giữ lại. `Chưa xác minh` nghĩa là một lần tải lại hoặc lượt kiểm thất bại hay chưa trọn, nên lỗi trước được giữ nguyên chứ không bị xoá. `Xuất hiện lại` nghĩa là một lỗi đã xử lý quay lại ở phiên bản sau.
  Bỏ qua chỉ áp dụng cho phiên bản artifact hiện tại; phiên bản sau sẽ hiện lại lỗi nếu vẫn phát hiện được. Lượt kiểm ở khổ màn hình này không bao giờ xoá lỗi tìm thấy ở khổ khác, và khổ màn hình bị bỏ khỏi tập chẩn đoán đã cấu hình (`FOLIO_AXI_DIAGNOSTIC_VIEWPORTS`, mặc định là tất cả) được đánh dấu lỗi thời kèm lý do rõ ràng, chứ không bị hiểu thành đã sửa.
- **Chú giải phiên bản** - Tuỳ chọn bật. Sau mỗi vòng phản hồi, agent tạo lại cả tệp, và một chỗ sửa một câu sẽ khó thấy trên artifact dài. Agent có thể khai báo những gì nó đã đổi ngay trong artifact: một mảng `<script type="application/json" data-lavish-revisions>` gồm các mục `{ id, label, timestamp, summary }`, cộng với `data-lavish-revision="<id>"` trên mỗi khối nó đã sửa hoặc thêm. Chạy `folio-axi design` để lấy đoạn mã mẫu.
  Khi đó nút **Phiên bản** xuất hiện trên thanh trên cùng, với bảng chú giải liệt kê từng vòng - ô màu, nhãn, thời gian và tóm tắt của agent - và **Chỉ chỗ** lần lượt đi qua các khối đã đổi của vòng đó, làm nháy từng khối một.
  Ô màu của mỗi phiên bản có kiểu viền và hoa văn tô riêng ngoài màu sắc, nên các vòng vẫn phân biệt được khi không nhìn màu. Artifact không có danh sách phiên bản thì không hiện nút và không bị ảnh hưởng gì khác, danh sách sai định dạng bị bỏ qua chứ không báo thành lỗi, và tối đa 6 phiên bản được liệt kê - mỗi phiên bản một ô màu phân biệt được.
  Folio không bao giờ chèn đánh dấu vào artifact cho việc này: bảng chú giải nằm ở khung review trên trình duyệt, nên trang được phục vụ vẫn y hệt tệp đã lưu, còn danh sách và các dấu đi theo tệp khi xuất.
- **Tiêu đề và biểu tượng tab cập nhật trực tiếp** - Tuỳ chọn bật. Khi artifact tải xong, tab trình duyệt lấy `<title>` và `<link rel="icon">` đầu tiên của nó. Artifact chạy lâu có thể giữ tab luôn cập nhật sau đó bằng `window.lavish.setDocumentMeta({ title, icon })`: một chuỗi sẽ đặt trường đó (tiêu đề rỗng sau khi cắt khoảng trắng sẽ khôi phục tiêu đề lúc tải), `null` khôi phục giá trị lúc tải, còn trường không truyền thì giữ nguyên. Tiêu đề bị cắt còn 120 ký tự và hiện dạng `<title> · Folio`; biểu tượng phải là URL `data:image/svg+xml` dài tối đa 8192 ký tự. Mọi giá trị khác bị bỏ qua. Giá trị giữ nguyên tới lần gọi sau hoặc tới khi chính tab tải lại, nên hãy gọi lại sau mỗi lần cập nhật trang. Lệnh gọi không làm gì khi trang không mở trong Folio, nên hãy kiểm tra tính năng bằng `window.lavish?.setDocumentMeta?.(...)`.
- **Tài nguyên cục bộ** - Chép ảnh, CSS, phông chữ và script cục bộ vào cạnh artifact HTML rồi tham chiếu bằng đường dẫn tương đối từ thư mục đó; đường dẫn bắt đầu từ gốc như `/assets/logo.png` sẽ không tìm thấy qua route artifact của Folio.
- **Xuất và chia sẻ** - `folio-axi export` ghi ra `<name>.export.html`: chỉ nhúng các tài nguyên cục bộ, gỡ SDK chú thích, và để nguyên các tham chiếu CDN/phông chữ từ xa dưới dạng link, vẫn cần mạng để tải.
  `folio-axi share` xuất bản đúng bản HTML đã nhúng tài nguyên cục bộ đó lên [ht-ml.app](https://ht-ml.app), một dịch vụ lưu trữ của bên thứ ba, không thuộc Folio.
  Xuất bản sẽ gửi artifact lên server của ht-ml.app, mặc định là công khai, hoặc riêng tư có mật khẩu với `--private` (Folio tạo mật khẩu và trả về một lần, trong output của lệnh và trong hộp thoại xuất bản trên trình duyệt) hay `--password <pw>` (mật khẩu bạn tự đặt, không bao giờ in lại). Mật khẩu được tạo là bí mật dùng chung: đưa cho người cần đọc trang, và hãy biết trước rằng nó sẽ xuất hiện trong transcript của agent, vì agent phải chuyển lại nó. Folio không lưu mật khẩu.
  Phản hồi có một `update_key` bí mật, chỉ hiện một lần. Hãy giữ nó để sau này xuất bản lại đúng URL đó bằng `--site <site_id> --update-key <key>`; lệnh này thay HTML tại chỗ và giữ nguyên mật khẩu, trừ khi bạn truyền `--private` (đổi sang một mật khẩu mới được tạo) hoặc `--password <pw>` (đặt mật khẩu). Khoá một trang vốn công khai không có hiệu lực ngay - trang có thể vẫn được trả từ cache CDN của ht-ml.app trong vài phút sau khi đặt mật khẩu - còn trang vốn đã riêng tư thì không có bản cache như vậy.
  Không gỡ được mật khẩu của trang: ht-ml.app nhận yêu cầu xoá mật khẩu nhưng lặng lẽ bỏ qua, nên Folio không cung cấp cách nào biến trang riêng tư thành công khai, thay vì báo với bạn là đã làm một việc mà máy chủ không làm. Nếu cần URL công khai, hãy xuất bản thành trang mới.
  ht-ml.app không có endpoint xoá, nên `--unpublish --site <site_id> --update-key <key>` thay trang bằng một trang giữ chỗ ngắn và khoá nó sau một mật khẩu ngẫu nhiên đã bỏ đi, chứ không gỡ trang: URL vẫn truy cập được và máy chủ vẫn giữ những gì đã xuất bản. Việc thay nội dung có hiệu lực ngay, nhưng việc khoá thì không: trang vốn công khai có thể vẫn trả trang giữ chỗ cho khách không có mật khẩu từ cache CDN của ht-ml.app trong vài phút sau đó. `update_key` cộng với `--private` sẽ xuất bản lại nội dung thật sau một mật khẩu mới mà bạn có thể chia sẻ.
  Khi đóng gói, Folio không bao giờ tải URL từ xa, bản thân Folio không đặt CSP, việc đọc tệp cục bộ bị giới hạn phạm vi và dung lượng, và các đường dẫn `file://` tuyệt đối nằm ngoài các tham chiếu tài nguyên đã nhúng an toàn sẽ bị che trước khi xuất.
  Giới hạn nhúng cho mỗi tài nguyên và mỗi gói mặc định là 10 MB và 25 MB, đổi được bằng `FOLIO_AXI_EXPORT_MAX_ASSET_BYTES` và `FOLIO_AXI_EXPORT_MAX_BUNDLE_BYTES`.
  Tài nguyên cục bộ không tìm thấy hoặc các thông báo khi xuất, như thẻ meta CSP do tác giả đặt hay URL tệp đã bị che, được nêu trong output của lệnh hoặc trên trình duyệt.
  Dùng `--token` hoặc `FOLIO_AXI_HTML_APP_TOKEN` cho bearer token tuỳ chọn khi xuất bản trang mới (xuất bản lại hoặc `--unpublish` thì xác thực bằng `update_key` và từ chối `--token`); đặt `FOLIO_AXI_HTML_APP_API_URL` để thay địa chỉ gốc API của ht-ml.app và trỏ `share` tới backend do bạn quản lý (xem [Tự host backend chia sẻ](docs/self-hosting-share.md) để biết giao kèo backend phải đáp ứng).
- **Tải lại tự động** - Mặc định Folio theo dõi tệp artifact HTML và giữ ngữ cảnh review qua các lần tải lại: vị trí cuộn của iframe artifact, chữ chưa gửi trong thẻ chú thích đang mở, và câu trả lời cho các điều khiển `data-lavish-question` (trạng thái form do ứng dụng tự quản thì không đụng tới). Trạng thái review được hỗ trợ và hàng chờ chưa gửi được lưu trong `sessionStorage` của tab đó, và còn nguyên sau khi tải lại toàn bộ trang review trong cùng tab nếu trình duyệt cho dùng bộ nhớ. Chúng không được chia sẻ sang tab hay cửa sổ khác; đóng tab đang giữ chúng có thể làm mất phần chưa gửi. Trong lúc một lô lỗi bố cục đã xếp hàng còn đang chờ, các lần lưu sát nhau được gộp lại để một lô sửa chỉ tốn một lần làm mới. Muốn tải lại cả khi các tài nguyên bên cạnh thay đổi, thêm `data-lavish-live-reload-root` vào phần tử gốc hoặc `<meta name="lavish-live-reload" content="root">`.
  Nếu phần tử mà một chú thích chưa gửi gắn vào đã biến mất hẳn khỏi artifact, Folio không mở lại được thẻ đó; còn nếu artifact thay một ghi chú đang chờ trong lúc bạn đang sửa nó, bản thay thế được giữ đúng như artifact gửi. Trường hợp nào thì Folio cũng ghi phần chữ bạn đã sửa vào khung hội thoại dưới mục **Chú thích chưa gửi** - chọn được, không bao giờ ghi đè lên thứ bạn đã gõ, và được giữ qua các lần tải lại; không ghi chú nào bị bỏ đi để nhường chỗ cho ghi chú mới hơn, và ghi chú nào trình duyệt từ chối lưu thì sẽ báo như vậy ngay chỗ nó hiện.
- **Điều khiển phản hồi** - Điều khiển gốc (radio, checkbox, input, select, button, label, summary của khối mở/đóng, contenteditable) và widget tự làm có ARIA role tương tác (`button`, `checkbox`, `combobox`, `menuitem`, `menuitemcheckbox`, `menuitemradio`, `option`, `radio`, `switch`, `tab`, `treeitem`) tự động dùng được để tương tác, nên không cần `data-lavish-action`. Link (`<a href>`) vẫn chú thích được khi mang một trong các role này hoặc nằm trong widget như vậy.
  Artifact có thể bắt đầu ở chế độ xem (explore) bằng `data-lavish-annotate="off"` trên phần tử gốc `<html>`, để những cú bấm vô tình không mở thẻ chú thích. Chú thích mặc định bật (hoặc khi đặt `"on"`); giá trị lạ được coi là bật. Thanh công cụ phản ánh mặc định của trang và có thể ghi đè nó; lựa chọn của người review được giữ qua các lần tải lại artifact trong trang review đó. Xem `folio-axi playbook input` để biết hướng dẫn cho người viết trang.
  Với lựa chọn có thể đổi lại, cho các cú bấm vào phương án cập nhật trạng thái cục bộ, rồi xếp hàng đúng một câu trả lời cuối từ nút submit hoặc nút Queue answer của từng câu hỏi bằng `window.lavish.queuePrompt()`.
  Nếu có người có thể mở artifact cần quyết định dưới dạng tệp HTML độc lập, `folio-axi playbook input` có sẵn nút Copy all answers tuỳ chọn để họ chép các câu trả lời trong form rồi dán lại vào chat.
  Chỉ đánh dấu `data-lavish-action` cho các phần tử bấm được tự làm (không phải điều khiển gốc) để Folio không chú thích chúng, và dùng `data-lavish-question` hoặc `queueKey` khi các lần cập nhật trước lúc gửi cho cùng một câu hỏi cần thay thế nhau.
  Mọi thứ bạn gửi đều thuộc cuộc hội thoại: ghi chú trên một phần tử, một đoạn chữ đã chọn, một ô bảng, một nút sơ đồ, một bảng trắng, một lô lỗi bố cục hay một tin nhắn từ ô soạn tin, mỗi thứ thành một bong bóng ở phía bạn trong khung Hội thoại, kèm một dòng neo cho biết nó gắn vào đâu (tag phần tử, đoạn chữ đã chọn, ô bảng, nút sơ đồ, bảng trắng hay lỗi bố cục), một đoạn trích, và selector khi rê chuột nếu có. Ghi chú đã xếp hàng mà chưa gửi nằm ở cuối hội thoại thành bong bóng viền nét đứt có nhãn **Đang chờ**, kèm nút sửa và nút xoá. Bấm vào bong bóng hoặc nút sửa sẽ mở phần chữ để sửa tại chỗ và cuộn artifact tới phần tử mà ghi chú trỏ tới; bấm lại phần tử đó ở chế độ chú thích sẽ mở đúng ghi chú ấy chứ không mở thẻ mới. Lưu một ghi chú không có chữ và không có ảnh sẽ xoá nó, và **Gửi** giao phần đang sửa dở đúng như đã gõ. Trong lúc lô của nó đang được gửi, ghi chú hiện **Đang gửi** và không sửa được nữa; khi server đã nhận, nó chuyển tại chỗ thành bong bóng đã gửi ở mọi tab của phiên. Khung giữ transcript lưu gần nhất tới 5 MiB; bong bóng cũ hơn không hiện nữa, nhưng ghi chú đã được nhận vẫn được chốt và không bị gửi hai lần. Câu trả lời của agent được hiển thị theo một tập con Markdown nhỏ - đoạn văn, ngắt dòng, tiêu đề thành dòng mở đầu in đậm, danh sách gạch đầu dòng và đánh số, code khối và code trong dòng, in đậm, in nghiêng và link http(s) - còn bảng, ảnh và HTML thô giữ nguyên dạng chữ agent đã viết; tin nhắn của chính bạn giữ ngắt dòng và không bao giờ bị phân tích cú pháp.
  Trên màn hình rộng, hội thoại và các ghi chú đang chờ dùng chung một khung Hội thoại cuộn được, nằm trên ô soạn tin cố định, nên hàng chờ phản hồi dài không đẩy ô nhập hay các nút gửi ra khỏi màn hình. Nút thanh bên trên thanh trên cùng ẩn khung đó để artifact chiếm trọn chiều rộng, và hiện lại khi bấm lần nữa; trong lúc khung ẩn, nút đếm số ghi chú đang chờ hoặc đánh dấu câu trả lời của agent mà bạn chưa xem, và lựa chọn này được trình duyệt nhớ cho mọi lượt review.
  Khung review đặt các thao tác biên tập trong menu tràn (chép đường dẫn, tải lại nội dung, chép ảnh chụp DOM, xuất HTML độc lập, xuất bản link, kết thúc phiên), còn ô soạn tin có nút **Gửi và kết thúc** cạnh **Gửi cho agent** để gửi các prompt đang chờ cùng với ghi nhận rằng người dùng kết thúc phiên. Khi **Gửi và kết thúc** bắt đầu, Folio tạm ngưng nhận phản hồi mới, chờ tối đa 5 giây cho phần phản hồi đang chuẩn bị dở, giữ nguyên mọi bản nháp chú thích đang mở cho tới khi giao thành công, rồi giữ chặt đúng lô cuối đó. Một lượt giữ chỗ đã hoàn tất vẫn còn sau khi tải lại trang, kể cả khi các prompt của nó đã được giao và chỉ còn việc kết thúc đang chờ; phần chuẩn bị chưa xong thì không được khôi phục. Nếu chuẩn bị quá hạn, Folio để lượt review vẫn mở, hàng chờ hiện có vẫn sửa được, kèm thông báo lỗi hiển thị rõ. Khi giao thất bại tạm thời, chỉ được thử lại đúng lô cuối đó qua **Gửi và kết thúc** cho tới khi thành công. Nếu ảnh chụp DOM làm yêu cầu quá lớn (HTTP 413), Folio thử lại đúng lô đó một lần mà không kèm ảnh chụp tuỳ chọn. Còn khi tệp đính kèm bị từ chối với lý do xử lý được (HTTP 400), xung đột lựa chọn lỗi bố cục khôi phục được (HTTP 409), hoặc lỗi 413 không khôi phục được, thì lượt giữ chỗ cuối bị huỷ mà phiên không kết thúc, các prompt vẫn nằm trong hàng chờ, và các thao tác sửa, xoá, **Gửi cho agent**, **Gửi và kết thúc** và **Kết thúc phiên** được bật lại để người review sửa hoặc bỏ phản hồi đã cũ trước khi gửi lại.
  Ghi chú đang chờ chưa gửi thuộc về tab nơi bạn nhập, không phải bản nháp chung trên server. Bấm **Gửi cho agent** khi hàng chờ trống sẽ báo "Không có gì đang chờ trong thẻ này." rồi tới đúng câu đã nêu: "Câu trả lời chưa gửi nằm lại ở thẻ hoặc cửa sổ nơi bạn nhập; tiếp quản ở cửa sổ khác không mang chúng theo." Chỉ bật chế độ chú thích thì chưa xếp ghi chú vào hàng chờ, nên trước hết hãy dùng thao tác **Xếp hàng** của thẻ chú thích. Chỉ phản hồi đã được nhận qua **Gửi** mới được lưu trên server để giao cho agent.
  Phản hồi từ ô soạn tin được hiện rõ trong hàng chờ trước khi ô nhập được xoá, và ở trong hàng chờ cho tới khi được xác nhận. Khi gửi, Folio chờ tối đa 5 giây để lấy ảnh chụp DOM của artifact, rồi giao luôn không kèm ngữ cảnh tuỳ chọn đó nếu khung không còn trả lời; ảnh chụp đến muộn không thể gửi lô đó hai lần. POST thất bại hoặc chưa được xác nhận sẽ giữ nguyên hàng chờ và hiện hướng dẫn khôi phục cố định, trừ khi một lần đồng bộ transcript chứng minh server đã nhận phản hồi đó.
- **Review trên điện thoại** - Khi rộng dưới 860px, artifact chiếm cả màn hình phía trên thanh **Hội thoại**, và hội thoại mở thành tấm trượt từ dưới lên đè lên artifact: chạm vào thanh, vuốt lên, hoặc bấm mũi tên để kéo tấm lên; chạm vào artifact đang bị làm mờ, vuốt tấm xuống, bấm mũi tên, hoặc nhấn Escape để hạ xuống. Khi tấm đang hạ, thanh báo những gì quan trọng - bao nhiêu prompt đang chờ, có câu trả lời đến trong lúc bạn đang đọc, hay những gì bạn gửi đã được lưu cho agent - và tấm vẫn mở sau khi tải lại trang review. Tấm tự co giãn theo vùng nhìn thấy và tôn trọng vùng an toàn (safe-area inset); nếu bàn phím hay tệp đính kèm chừa ít chỗ, nội dung hội thoại co lại hoặc cuộn, còn các nút gửi vẫn ghim phía trên mép dưới. Ở chế độ nằm ngang, tấm che cả thanh trên cùng. Màn hình rộng hơn giữ bố cục hai cột cạnh nhau.
- **Phím tắt** - Trong ô soạn tin của khung review, Enter gửi các prompt đang chờ, Shift+Enter xuống dòng.
  Trong thẻ chú thích, Enter xếp chú thích vào hàng chờ, Shift+Enter xuống dòng, và Ctrl+Enter (Cmd+Enter trên macOS) xếp nó vào hàng chờ rồi gửi ngay mọi prompt đang chờ. Escape đóng thẻ, giống nút Huỷ, nhưng chỉ khi thẻ trống (không chữ, không tệp đính kèm); khi còn chữ chưa gửi hoặc có tệp đính kèm, Escape không làm gì để khỏi lỡ tay bỏ mất nội dung.
  Khi sửa một ghi chú đang chờ, Enter lưu, Shift+Enter xuống dòng, Escape bỏ phần vừa sửa.
  Cmd+I hoặc Ctrl+I chuyển qua lại giữa chế độ chú thích và chế độ xem, từ khung review hay từ iframe artifact đều được, kể cả khi con trỏ đang ở trong textarea hoặc một điều khiển.
  Ở chế độ chú thích, bấm thường vào link sẽ chú thích link đó; Ctrl+bấm (Cmd+bấm trên macOS) thì mở link, sang tab mới như trình duyệt vẫn làm, mà không rời chế độ chú thích. Ngoài macOS, Meta+bấm (phím Windows hoặc Super) chú thích như bấm thường. Thẻ chú thích của link http(s) có ghi điều này và có nút **Mở link** để mở link trong tab mới; nút này cũng đóng thẻ nếu thẻ chưa có chữ hay ảnh.
- **Trạng thái agent** - Trình duyệt báo khi phiên agent không chờ trên trang này và rằng những gì bạn gửi được lưu cho lượt hoạt động kế tiếp của nó, và vẫn để các thao tác phản hồi của người dùng dùng được trong lúc agent đang làm. Phản hồi đã được nhận qua **Gửi** nằm trong hàng chờ trên server cho lần giao `folio-axi poll` thành công kế tiếp, kể cả qua các lần tải lại; ghi chú chưa từng gửi vẫn ở tab nơi chúng được tạo. Câu trả lời của agent chốt lại phần việc đã giao và đưa trạng thái về chờ (xem mục Lệnh để biết các lệnh reply và poll). Khi Claude Code báo phiên agent làm chủ trang đã kết thúc, dải thông báo cạnh ô soạn tin nói rõ điều đó và có nút **Chép câu trả lời**: các ghi chú chưa agent nào đọc, dạng chữ thường để dán vào một phiên mới. Phiên mới mở trong cùng thư mục được hook SessionStart báo có phản hồi đang chờ. Thẻ báo phiên đã kết thúc cũng có nút đó khi còn câu trả lời chưa được đọc, và hiện câu trả lời cuối của agent. Bộ nghe là tiến trình do supervisor quản lý được hiện là bộ nghe ngoài, chứ không phải một lượt captain đang rảnh.
- **Biên nhận giao** - Mỗi ghi chú bạn đã gửi có ba emoji bên dưới, sáng lần lượt: 👀 **Đã thấy** khi một `folio-axi poll` đã nhận ghi chú, 🛠️ **Đang làm** khi tệp artifact thay đổi sau đó, và ✅ **Xong** khi agent trả lời. Bước chưa xảy ra là chính emoji đó nhưng tô xám. Cả ba đều dựa trên những gì server quan sát được; agent không phải làm thêm gì. Cho tới khi 👀 sáng, dòng này cho biết chuyện gì sẽ xảy ra tiếp: ghi chú đã lưu và sẽ được giao khi agent hoạt động trở lại, hoặc agent đang bận và sẽ nhận nó ở lần poll tới. Ghi chú được trả lời mà không đụng tới artifact sẽ đi từ Đã thấy sang Xong, Đang làm vẫn xám. Một câu trả lời đánh dấu Xong cho mọi ghi chú agent đã thấy, không phải các ghi chú còn chờ poll. Mỗi emoji nêu tên bước và thời điểm khi rê chuột và với trình đọc màn hình. Ghi chú gửi từ trước khi có biên nhận thì không có dòng biên nhận.
  Poll vẫn tiếp tục chờ khi tab review cuối cùng đóng, điện thoại khoá màn hình hay một pane bị ẩn, vì poll là thứ đánh thức phiên agent đang rảnh. Muốn poll nhả ra thay vì chờ, đặt `FOLIO_AXI_DISCONNECT_GRACE_MS` trên server thành một khoảng thời gian tính bằng mili giây: khi đó poll trả về `browser_disconnected` mà không kết thúc phiên (vẫn tiếp tục được), và agent hỏi nên mở lại hay kết thúc chứ không tự ý hành động.
  Poll không đặt hạn chờ luôn in ngay một dòng thông báo ra stderr để thấy rõ là nó không bị treo; nó chỉ in thêm nhịp chờ định kỳ ra stderr khi chạy trong terminal tương tác, nên khi stderr bị chuyển qua pipe (như dưới harness của agent) thì output thu được không lẫn nhịp chờ. Stdout luôn dành riêng cho phản hồi cuối; nếu poll bị ngắt hoặc hết hạn trước khi phản hồi tới, hãy chạy lại vì phản hồi vẫn nằm trong hàng chờ cho tới khi được giao. Lần giao qua poll sẽ tiêu thụ phản hồi, nên hãy đọc trọn phản hồi trước khi cắt bớt hay lọc nó.
  Hướng dẫn riêng cho Codex giữ poll đó gắn với lượt đang chạy thay vì giấu vào tác vụ nền, vì tác vụ nền đã xong có thể không đánh thức lại agent.
- **Phép tắc khi kết thúc phiên** - Folio ghi lại ai đã kết thúc phiên: người bấm **Kết thúc phiên** (hoặc **Gửi và kết thúc**) trên trình duyệt là kết thúc do người dùng, còn `folio-axi end <html-file>` là kết thúc do agent.
  Khi bên nào kết thúc phiên, mọi tab review đang mở đều chuyển rõ sang chỉ đọc và tắt các điều khiển phản hồi; phản hồi gửi sau khi kết thúc bị từ chối, chứ không được nhận khi chẳng còn agent nào để nhận.
  Khi bản ghi kết thúc còn tồn tại, một lệnh `folio-axi <html-file>` thông thường sau lần kết thúc do người dùng sẽ từ chối mở lại trình duyệt và trả về hướng dẫn; chỉ truyền `--reopen` khi người dùng muốn review thêm hoặc có điều quan trọng cần họ xem tận mắt. Bản ghi kết thúc đủ điều kiện được dọn lúc khởi động sau `FOLIO_AXI_ENDED_RETENTION_DAYS` (mặc định 7 ngày); khi đã dọn, lệnh mở thông thường sẽ bắt đầu một phiên mới.
  Phiên do agent kết thúc vẫn mở lại bình thường như trước.
  Phản hồi `ended` của `folio-axi poll` và phản hồi `feedback` cho lô cuối trước khi kết thúc đều kèm hướng dẫn `next_step`, bảo agent ngừng poll và gửi các cập nhật còn lại trong chat thay vì mở lại.
- **Đích chính xác** - Chú thích chữ gồm đoạn chữ đã chọn cộng với các neo vùng chọn, và vùng chọn chữ chỉ mang các neo đó.
  Bấm vào một phần tử trong bảng cũng mang theo tên hàng và cột hiển thị của ô, bên cạnh bộ định vị CSS chính xác, nên hàng bị lọc hay sắp xếp không làm phản hồi trông như chỉ nhầm chỗ.
  Khi ô gộp khiến tên hàng hay tên cột không rõ ràng, Folio bỏ tên đó chứ không đoán; `<th scope="row">` khai báo rõ vẫn có hiệu lực ngay cả khi `rowspan` làm vị trí hàng không rõ.
  Bộ định vị CSS vẫn trỏ đúng phần tử bạn bấm, nên chú thích thiếu tên chỉ kém mô tả hơn, không bao giờ bị gắn nhãn sai.
- **Ảnh đính kèm** - Đính kèm ảnh tham khảo (PNG, JPEG, WebP) ở ô soạn tin của khung Hội thoại hoặc trong thẻ chú thích bằng cách dán, kéo thả, hoặc dùng nút chọn ảnh; mỗi ảnh hiện thành một chip thu nhỏ với các trạng thái đang tải lên, bỏ, thử lại và lỗi. Nếu sau này một ảnh đã gửi bị dọn do giới hạn lưu trữ tệp đính kèm, ảnh thu nhỏ của nó trong lịch sử transcript thành ô giữ chỗ **Ảnh đã hết hạn**.
  Khi dán nội dung vừa có chữ vừa có ảnh, chữ được giữ còn ảnh được đính kèm (tên hay đường dẫn của chính tệp đã chép được coi là chữ giữ chỗ và không được dán). Tin nhắn hội thoại có thể có cả chữ và ảnh, hoặc chỉ ảnh.
  Ảnh được lưu trong thư mục trạng thái, và prompt đang chờ mang theo `path` tuyệt đối do server tạo cùng `id` là mã băm nội dung (kèm mime và kích thước) - không bao giờ mang byte thô - nên `folio-axi poll` đưa cho agent một đường dẫn tệp cục bộ để mở.
  Các giới hạn là `FOLIO_AXI_MAX_ATTACHMENT_BYTES` (mặc định 10 MiB mỗi ảnh), `FOLIO_AXI_MAX_ATTACHMENTS_PER_PROMPT` (mặc định 4) và `FOLIO_AXI_MAX_PROMPT_ATTACHMENT_BYTES` (mặc định 25 MiB mỗi prompt); nếu thiếu bất kỳ ảnh nào hoặc prompt nào vượt giới hạn số lượng hay dung lượng, cả lô gửi bị từ chối, hàng chờ được giữ nguyên và lý do hiện ở ô soạn tin, chứ không lặng lẽ bỏ ảnh.
  Để chống lạm dụng phía trình duyệt, mỗi trang khung review cho phép 30 lần thử tải lên trong mỗi phút trượt, 4 lượt tải lên cùng lúc, và tổng 256 MiB ảnh đã thử tải trong suốt vòng đời trang; lượt tải lên bị từ chối vẫn hiện để thử lại hoặc bỏ.
  Tệp đính kèm không còn được tham chiếu hết hạn sau `FOLIO_AXI_ATTACHMENT_TTL_MS` (mặc định 7 ngày; `0`/`off` để tắt); `FOLIO_AXI_MAX_ATTACHMENT_DISK_MB` (mặc định 512 MiB; `0`/`off` để tắt) giới hạn tổng dung lượng đĩa cho tệp đính kèm và có thể dọn sớm hơn các ảnh cũ không còn được tham chiếu.
  Giới hạn này được áp ngay khi tải ảnh lên chứ không chỉ theo định kỳ: lượt tải lên trước hết thu hồi các tệp không còn được tham chiếu (cũ nhất trước, và không bao giờ đụng tệp thêm vào trong vòng một giờ qua), nếu vẫn không đủ chỗ thì lượt tải lên đó bị từ chối kèm lỗi hết dung lượng trên chip, chứ không bỏ một ảnh người dùng sắp gửi.
- **Sơ đồ Mermaid** - Bảng trắng là tuỳ chọn bật: agent chỉ viết sơ đồ bằng Mermaid khi bạn yêu cầu bảng trắng sửa được; còn lại, hình minh hoạ SVG inline vẽ tay là dạng hình mặc định.
  Trong trình duyệt Folio, mọi sơ đồ Mermaid đã render trong khối `.mermaid` trở thành một bảng trắng Excalidraw nhúng, sửa được.
  Bấm vào sơ đồ để mở khoá chỉnh sửa, và dùng thao tác Fullscreen của nó để sửa trên toàn màn hình.
  Cảnh bảng trắng tự lưu trên máy.
  Nếu một lần tải lại tự động làm đổi mã Mermaid, bảng trắng chưa bị sửa sẽ lặng lẽ chuyển đổi lại theo sơ đồ mới. Nếu người review đã sửa cảnh, khi mở lại họ được chọn chuyển đổi lại và bỏ phần sửa đã lưu, hoặc tiếp tục sửa cảnh đã lưu.
  Dùng **Queue feedback** để thêm vào khung Hội thoại một bản tóm tắt chỉnh sửa có giới hạn độ dài, cùng đường dẫn cục bộ tới tệp cảnh `.excalidraw` và ảnh xem trước PNG, rồi bấm **Gửi cho agent** để giao.
  Agent cập nhật mã Mermaid của artifact, và mã này vẫn là nguồn chuẩn.
  Sơ đồ flowchart, sequence, class, ER và state được chuyển thành hình sửa được; các loại sơ đồ khác là ảnh mà người review có thể vẽ lên và chú thích.
  Folio chỉ đổi phần hiển thị trên trình duyệt, nên artifact đã lưu, bản độc lập và bản xuất vẫn hiển thị Mermaid thường.
- **Thư viện bảng trắng** - Chép các tệp thư viện Excalidraw (`.excalidrawlib`, ví dụ từ [libraries.excalidraw.com](https://libraries.excalidraw.com)) vào `~/.folio-axi/excalidraw-libraries/`, hoặc `FOLIO_AXI_STATE_DIR/excalidraw-libraries/` nếu đã đặt biến này. Khung thư viện của mọi bảng trắng liệt kê các mục trong đó, và mục nào bạn thả lên canvas sẽ tới agent theo tên trong bản tóm tắt chỉnh sửa.
  Agent chạy `folio-axi libraries` để tìm tham chiếu mục, và có thể hiện một nút flowchart thành một trong các biểu tượng đó bằng cách thêm comment `%% lavish-icon <node-id> <library-id>/<item name>` vào mã Mermaid. Mermaid bỏ qua comment này, nên bản đã lưu, bản xuất, bản chia sẻ và các bảng trắng không có thư viện đó đều hiện nút thường.
  Folio chỉ đọc thư mục đó và không bao giờ tự tải thư viện. Tệp lớn hơn 10 MB, phần vượt tổng 25 MB hoặc 5.000 mục, và tệp không đọc được đều bị bỏ qua; `folio-axi libraries` liệt kê từng tệp bị bỏ qua kèm lý do.
  Mỗi thư viện có điều khoản riêng của tác giả (ví dụ AWS Architecture Icons theo điều khoản sử dụng của chính AWS), nên hãy xem kỹ trước khi dùng.
- **Tự dọn server** - Server chạy tách rời sẽ dừng khi phiên cuối cùng kết thúc mà không còn gì kết nối, hoặc sau `FOLIO_AXI_IDLE_TIMEOUT_MS` (mặc định 30 phút) không có kết nối trình duyệt hay poll nào.
  Đặt `FOLIO_AXI_IDLE_TIMEOUT_MS=0` hoặc `off` để tắt việc tự dừng khi rảnh.
- **Nâng cấp server** - Một server nền phục vụ mọi phiên, nên nâng cấp `folio-axi` trong lúc đang có lượt review mở sẽ khiến lệnh `folio-axi <html-file>` kế tiếp thay server đó. Chỉ CLI mới hơn mới thay server cũ hơn: CLI cũ hơn server đang chạy thì dùng luôn server đó, nên hai phiên bản cài trên cùng một máy không khởi động lại server của nhau. Các bản phát hành tới hết 0.1.86 vẫn thay server khác phiên bản, nên việc khởi động lại qua lại từng lượt này chỉ dừng khi cả hai phiên bản đã cài đều có bản sửa này. Chỉ trang review của artifact đang được mở tự tải lại khi server thay thế trả lời - và ngay cả trang đó cũng không tự tải lại khi bạn đang mở chữ chú thích chưa gửi; trường hợp đó nó hiện cùng dải thông báo để bạn tự quyết định tải lại. Mọi trang review đang mở khác vẫn chạy và hiện dải thông báo "Folio đã được cập nhật. Trang này đang chạy bản trước.", kèm nút Kiểm tra và tải lại và nút Bỏ qua, nên không trang nào bạn đang đọc tự tải lại. Sau `folio-axi stop`, các trang đó báo Folio đã dừng và hãy tải lại sau khi khởi động lại nó, còn một lần khởi động lại chỉ để nhận bản build cục bộ thì báo đúng như vậy chứ không nhận là có cập nhật. Trang review đang mở mà server của nó đơn giản là biến mất - tự dừng khi rảnh, bị crash, máy ngủ - sẽ hiện cùng dải thông báo đó khi kết nối lại đã thất bại vài giây, thay vì lặng lẽ thử lại một server đã chết trong khi trông vẫn bình thường; dải tự biến mất nếu server quay lại, và nếu bạn bỏ qua thì nó không hiện lại cho tới lúc đó.
  Trang còn dùng luồng sự kiện kiểu cũ sẽ tải lại một lần khi kết nối lại tới server thay thế, tự chuyển sang kênh truyền hiện tại mà không giữ lại kết nối HTTP. Nếu đang mở chữ chú thích chưa gửi, trang hiện dải thông báo trung tính rằng server đã khởi động lại và chờ bạn tải lại.
  Mọi nút **Kiểm tra và tải lại** đều hỏi server có đang chạy không trước khi chuyển trang; khi chưa có gì trả lời, trang ở nguyên chỗ và báo như vậy, còn lượt kiểm không nhận được câu trả lời nào thì báo đúng điều đó chứ không đoán.
  Các lệnh `folio-axi poll` đang chạy sẽ kết thúc với lỗi poll bị ngắt và chạy lại được an toàn; phản hồi server đã nhận vẫn nằm trong hàng chờ cho tới khi được giao, còn ghi chú chưa từng gửi và bản nháp chú thích được hỗ trợ vẫn còn sau khi tải lại trong cùng tab, như mô tả ở mục **Tải lại tự động**.
  Trang chờ server thay thế chứ không tải lại vào một cổng không có gì đang nghe, và bảo người dùng khởi động lại Folio nếu server không bao giờ quay lại.
- **Trạng thái lưu cục bộ** - Trạng thái phiên mặc định nằm trong `~/.folio-axi/`, hoặc `FOLIO_AXI_STATE_DIR` nếu đã đặt.
- **Khổ màn hình chẩn đoán** - `FOLIO_AXI_DIAGNOSTIC_VIEWPORTS` chọn những loại khổ màn hình mà hộp lỗi bố cục theo dõi (`mobile`, `compact`, `desktop`; ngăn cách bằng dấu phẩy, mặc định là tất cả). Cảnh báo có loại khổ bị bỏ khỏi tập này được đánh dấu lỗi thời kèm lý do rõ ràng, chứ không lặng lẽ bị hiểu là đã sửa.
- **Cổng server** - Đặt `FOLIO_AXI_PORT` để chọn cổng server; mặc định là `4388`.
- **Gắn địa chỉ mạng** - Khi Tailscale đang chạy, server review tự động chỉ nghe trên loopback (`127.0.0.1`) và địa chỉ IPv4 Tailscale của máy này - không bao giờ nghe trên `0.0.0.0` hay mọi interface. Link phiên được tạo dùng tên MagicDNS của máy, nên đó là URL mở được ngay từ điện thoại hay thiết bị khác trong cùng tailnet. Khi không có Tailscale hoặc Tailscale không chạy, Folio lặng lẽ quay về chỉ nghe loopback và không in URL cho điện thoại. Nếu Tailscale chạy mà MagicDNS không dùng được, Folio cảnh báo rõ rằng không truy cập được từ điện thoại và vẫn chỉ nghe loopback. Gắn ra ngoài loopback sẽ mở một server không xác thực, đọc và phục vụ được tệp cục bộ bất kỳ cho thiết bị nào với tới được nó, nên tailnet phải là mạng tin cậy. `FOLIO_AXI_HOST` đặt tường minh sẽ ghi đè việc tự gắn Tailscale; giá trị wildcard bị giới hạn về loopback, còn giá trị không phải wildcard chọn đúng địa chỉ cụ thể đó để gắn, và server cũng nghe trên loopback để mọi CLI cục bộ đều tìm thấy nó, bất kể `FOLIO_AXI_HOST` của CLI đó là gì. Địa chỉ không gắn được - địa chỉ tailnet khi tiến trình khác đang giữ nó, khi Tailscale đang khởi động lại, hoặc một hostname tường minh tạm thời không phân giải được - được báo thành `network_warning` trong output của `folio-axi <file>` và ghi vào `server.log`; trong lúc đó link phiên trỏ về loopback trừ khi `FOLIO_AXI_LINK_HOST` ghi đè, và server tiếp tục thử lại địa chỉ đó ở chế độ nền và thử ngay ở lần gọi CLI kế tiếp. Khi gắn được, cảnh báo tự xoá và các link phiên mới lại dùng địa chỉ đó, không cần khởi động lại. Nếu không listener nào gắn được, việc khởi động thất bại chứ không nhận là có server truy cập được. `FOLIO_AXI_LINK_HOST` quyết định host trong link khi tắt việc tự gắn Tailscale.
- **Một server cho mỗi cổng** - Các agent trên cùng một máy có thể chạy với `FOLIO_AXI_HOST` khác nhau, hoặc không đặt, mà vẫn dùng chung một server: trước khi khởi động server, CLI tìm server đang chạy trên host đã cấu hình, trên loopback và mọi địa chỉ cục bộ khác. Server đang chạy mà chưa từng được yêu cầu nghe trên địa chỉ do `FOLIO_AXI_HOST` của một CLI chỉ định sẽ bị thay một lần bằng server nghe trên địa chỉ đó cộng với mọi địa chỉ server cũ đã phục vụ, giữ nguyên mọi phiên. Các lần khởi động lại do nâng cấp hay đổi mạng cũng giữ mọi địa chỉ server cũ đã phục vụ theo cách đó, trừ địa chỉ không còn trên máy này. Chuyển sang một địa chỉ mà server đang chạy đã phục vụ, kể cả loopback, thì dùng lại server đó, nên muốn bỏ một địa chỉ thì chạy `folio-axi stop` trước. Server khác của cùng bản cài đặt (cùng thư mục trạng thái) được tìm thấy trên cùng cổng ở địa chỉ khác sẽ bị tắt qua endpoint shutdown của chính nó, sau khi server được giữ lại đã được cho phục vụ cả địa chỉ đó, để các link review đã phát ra ở đó vẫn dùng được. Server thuộc thư mục trạng thái khác mà có báo định danh bản cài đặt thì không bao giờ bị dùng, thay hay dừng: khi nó giữ loopback hoặc địa chỉ đã cấu hình, CLI báo lỗi nêu thư mục trạng thái của nó, khi đó hãy chọn `FOLIO_AXI_PORT` khác. Server cũ hơn không báo được định danh chỉ được coi là thuộc bản cài đặt này ở các địa chỉ điều khiển đó, để tương thích khi nâng cấp.
- **Host được phép** - Để chống DNS rebinding, server từ chối (`403`) mọi yêu cầu thiếu header `Host` hoặc có `Host` không thuộc danh sách nó trả lời: các tên loopback, cộng với địa chỉ IPv4 Tailscale cụ thể và tên MagicDNS khi listener Tailscale gắn thành công. Nếu bạn cấu hình reverse proxy hoặc một hostname có chủ đích khác, hãy liệt kê nó trong `FOLIO_AXI_ALLOWED_HOSTS` (ngăn cách bằng khoảng trắng). Sau reverse proxy, `X-Forwarded-Host` được chuyển tiếp cũng được kiểm theo cùng danh sách, nên hãy thêm hostname công khai vào đó và cấu hình proxy gửi nó cùng `X-Forwarded-Proto`. Đặt `FOLIO_AXI_ALLOWED_HOSTS` thành `*` để tắt hẳn việc kiểm tra, chỉ khi server nằm sau lớp xác thực hoặc proxy của riêng bạn. Các route thay đổi dữ liệu còn từ chối `Origin` hoặc `Referer` lạ nếu có (`403`); yêu cầu điều khiển không có header từ CLI vẫn được phép ở những chỗ có hỗ trợ.
- **Mở trình duyệt** - Đặt `FOLIO_AXI_NO_OPEN=1`, tương đương `--no-open`, để tạo hoặc tiếp tục một phiên mà không mở cửa sổ trình duyệt.
